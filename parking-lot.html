Parking Lot LLD

Interview notes from Hello Interview's breakdown, with Java code and my own suggestions.

Problem

Design a parking lot where vehicles of different types park. On entry the system assigns a compatible spot and issues a ticket. On exit it validates the ticket, charges by the hour (rounded up) and frees the spot.

Requirements

In scope

  • 3 vehicle types: Motorcycle, Car, Large
  • Auto-assign a compatible free spot on entry
  • Issue a ticket with a unique ID
  • Exit by ticket ID: validate, compute fee, free spot
  • Hourly rate, same for all, round up
  • Reject entry if no compatible spot
  • Reject exit if ticket invalid or already used

Out of scope

  • Payment processing
  • Gates, cameras, display boards, UI
  • Reservations / pre-booking
  • Lost tickets

Clarifying questions to ask: does the system assign spots? which vehicle types? how is pricing done? what if full / invalid ticket? lost ticket? what's out of scope?

Entities

EntityKindResponsibility
ParkingLotOrchestratorOwns spots, occupancy and active tickets. The only public API: enter(), exit().
ParkingSpotDataID + SpotType. Intrinsic properties only. Does not know if it's occupied.
TicketImmutable recordticketId, spotId, vehicleType, entryTime. No behavior.
VehicleType, SpotTypeEnumsKept separate even with the same values, so compatibility rules can diverge later.
Vehicle is not a class. It's external to the system; we only need its type. Over-modeling Vehicle (with plate, color, etc.) is a common mid-level red flag.

Key design decisions

QuestionChoiceWhy
Where does occupancy live?Orchestrator (Set<String> occupiedSpotIds)Occupancy is relational (a ticket references the spot), not intrinsic. Flag-on-spot is also defensible.
activeTickets: List or Map?Map<String,Ticket>Makes "lookup by ID" explicit. Perf difference is irrelevant at this scale.
Where is the fee computed?ParkingLot.computeFee()Not on Ticket (it's data). A PricingStrategy is the "great" answer once pricing varies.
Ticket → Spot reference?Store spotId onlyTickets are records, not navigational objects (Law of Demeter).
Money typelong centsNever double for money.
Double exitRemove ticket on exitA reused ID is simply "not found". Same error for invalid and used.

Flows

enter(vehicleType) spot = findAvailableSpot(type) → null? throw NoSpotAvailable (no state changed) occupiedSpotIds.add(spot.id) ticket = new Ticket(uuid, spot.id, type, now) activeTickets.put(ticket.id, ticket) → return ticket exit(ticketId) ticket = activeTickets.get(id) → null? throw InvalidTicket fee = ceil(hours(now - entry)) * rate occupiedSpotIds.remove(ticket.spotId) activeTickets.remove(id) → return fee

Java: baseline (as in the article)

Matches the article's design. synchronized is the simple, correct answer for multiple entrances.

Types.java
public enum VehicleType { MOTORCYCLE, CAR, LARGE }
public enum SpotType    { MOTORCYCLE, CAR, LARGE }

public final class ParkingSpot {
    private final String id;
    private final SpotType spotType;

    public ParkingSpot(String id, SpotType spotType) {
        this.id = Objects.requireNonNull(id);
        this.spotType = Objects.requireNonNull(spotType);
    }
    public String getId()           { return id; }
    public SpotType getSpotType()   { return spotType; }
}

// Java 16+ record: immutable, getters/equals/hashCode for free
public record Ticket(String id, String spotId, VehicleType vehicleType, Instant entryTime) {}

public class NoSpotAvailableException extends RuntimeException {
    public NoSpotAvailableException(VehicleType t) { super("No available spot for " + t); }
}
public class InvalidTicketException extends RuntimeException {
    public InvalidTicketException(String id) { super("Ticket not found or already used: " + id); }
}
ParkingLot.java
public class ParkingLot {
    private static final long MILLIS_PER_HOUR = 3_600_000L;

    private final List<ParkingSpot> spots;
    private final Set<String> occupiedSpotIds = new HashSet<>();
    private final Map<String, Ticket> activeTickets = new HashMap<>();
    private final long hourlyRateCents;
    private final Clock clock;   // injected so tests can control time

    public ParkingLot(List<ParkingSpot> spots, long hourlyRateCents, Clock clock) {
        this.spots = List.copyOf(spots);
        this.hourlyRateCents = hourlyRateCents;
        this.clock = clock;
    }

    public synchronized Ticket enter(VehicleType vehicleType) {
        ParkingSpot spot = findAvailableSpot(vehicleType);
        if (spot == null) throw new NoSpotAvailableException(vehicleType);

        occupiedSpotIds.add(spot.getId());
        Ticket ticket = new Ticket(UUID.randomUUID().toString(), spot.getId(),
                                   vehicleType, clock.instant());
        activeTickets.put(ticket.id(), ticket);
        return ticket;
    }

    public synchronized long exit(String ticketId) {
        if (ticketId == null || ticketId.isBlank()) throw new InvalidTicketException(ticketId);

        Ticket ticket = activeTickets.get(ticketId);
        if (ticket == null) throw new InvalidTicketException(ticketId);

        long fee = computeFee(ticket.entryTime(), clock.instant());
        occupiedSpotIds.remove(ticket.spotId());
        activeTickets.remove(ticketId);
        return fee;
    }

    private ParkingSpot findAvailableSpot(VehicleType vt) {
        SpotType required = toSpotType(vt);
        for (ParkingSpot s : spots) {
            if (s.getSpotType() == required && !occupiedSpotIds.contains(s.getId())) return s;
        }
        return null;
    }

    private static SpotType toSpotType(VehicleType vt) {
        return switch (vt) {
            case MOTORCYCLE -> SpotType.MOTORCYCLE;
            case CAR        -> SpotType.CAR;
            case LARGE      -> SpotType.LARGE;
        };
    }

    private long computeFee(Instant entry, Instant exit) {
        long ms = Duration.between(entry, exit).toMillis();
        long hours = (ms + MILLIS_PER_HOUR - 1) / MILLIS_PER_HOUR;  // ceil
        return Math.max(1, hours) * hourlyRateCents;               // min 1 hour
    }
}

Java: my improved version

Same public API, but O(1) allocation, lock-free concurrency, and pluggable pricing. Good to present as the "senior" evolution after the baseline works.

  • Free-spot pool per type: EnumMap<SpotType, Queue<ParkingSpot>>. poll() claims a spot atomically, so two entrances can never get the same spot.
  • ConcurrentHashMap.remove(id) on exit is atomic, so a double exit from two gates fails cleanly.
  • PricingStrategy absorbs per-vehicle rates, weekend pricing, etc. without touching ParkingLot.
Pricing.java
public interface PricingStrategy {
    long feeCents(Ticket ticket, Instant exitTime);
}

public final class HourlyPricing implements PricingStrategy {
    private static final long MILLIS_PER_HOUR = 3_600_000L;
    private final Map<VehicleType, Long> ratesCents;

    public HourlyPricing(Map<VehicleType, Long> ratesCents) {
        this.ratesCents = Map.copyOf(ratesCents);
    }
    public static HourlyPricing flat(long rateCents) {     // base requirement
        Map<VehicleType, Long> m = new EnumMap<>(VehicleType.class);
        for (VehicleType v : VehicleType.values()) m.put(v, rateCents);
        return new HourlyPricing(m);
    }

    @Override
    public long feeCents(Ticket t, Instant exitTime) {
        long ms = Duration.between(t.entryTime(), exitTime).toMillis();
        long hours = Math.max(1, (ms + MILLIS_PER_HOUR - 1) / MILLIS_PER_HOUR);
        return hours * ratesCents.get(t.vehicleType());
    }
}
ConcurrentParkingLot.java
public class ConcurrentParkingLot {
    private final Map<SpotType, Queue<ParkingSpot>> freeSpots = new EnumMap<>(SpotType.class);
    private final Map<String, ParkingSpot> spotsById = new HashMap<>();     // read-only after ctor
    private final Map<String, Ticket> activeTickets = new ConcurrentHashMap<>();
    private final PricingStrategy pricing;
    private final Clock clock;

    public ConcurrentParkingLot(List<ParkingSpot> spots, PricingStrategy pricing, Clock clock) {
        this.pricing = pricing;
        this.clock = clock;
        for (SpotType t : SpotType.values()) freeSpots.put(t, new ConcurrentLinkedQueue<>());
        for (ParkingSpot s : spots) {
            spotsById.put(s.getId(), s);
            freeSpots.get(s.getSpotType()).offer(s);
        }
    }

    public Ticket enter(VehicleType vt) {
        ParkingSpot spot = freeSpots.get(toSpotType(vt)).poll();   // atomic claim, O(1)
        if (spot == null) throw new NoSpotAvailableException(vt);

        Ticket t = new Ticket(UUID.randomUUID().toString(), spot.getId(), vt, clock.instant());
        activeTickets.put(t.id(), t);
        return t;
    }

    public long exit(String ticketId) {
        if (ticketId == null || ticketId.isBlank()) throw new InvalidTicketException(ticketId);

        Ticket t = activeTickets.remove(ticketId);                // atomic: 2nd exit sees null
        if (t == null) throw new InvalidTicketException(ticketId);

        long fee = pricing.feeCents(t, clock.instant());
        ParkingSpot spot = spotsById.get(t.spotId());
        freeSpots.get(spot.getSpotType()).offer(spot);           // return to pool
        return fee;
    }

    private static SpotType toSpotType(VehicleType vt) {
        return switch (vt) {
            case MOTORCYCLE -> SpotType.MOTORCYCLE;
            case CAR        -> SpotType.CAR;
            case LARGE      -> SpotType.LARGE;
        };
    }
}
Demo.java (trace from the article)
public static void main(String[] args) {
    Instant t0 = Instant.parse("2026-01-01T10:00:00Z");
    MutableClock clock = new MutableClock(t0);   // tiny Clock subclass with advance(Duration)

    var lot = new ConcurrentParkingLot(List.of(
            new ParkingSpot("A", SpotType.MOTORCYCLE),
            new ParkingSpot("B", SpotType.CAR),
            new ParkingSpot("C", SpotType.LARGE)),
        HourlyPricing.flat(500), clock);

    Ticket t = lot.enter(VehicleType.CAR);            // gets spot B
    clock.advance(Duration.ofMinutes(150));           // 2.5 h
    System.out.println(lot.exit(t.id()));             // 1500 (3 h × 500)

    lot.enter(VehicleType.CAR);
    try { lot.enter(VehicleType.CAR); }             // lot full for cars
    catch (NoSpotAvailableException e) { System.out.println(e.getMessage()); }
    try { lot.exit(t.id()); }                         // double exit
    catch (InvalidTicketException e) { System.out.println(e.getMessage()); }
}

Extensions (talk, don't build)

Multi-floor

Add ParkingFloor (floorNo, spots) between lot and spot. Spot IDs like 3-A15. Ticket and exit unchanged. Allocation via a SpotAllocationStrategy: lowest floor first, balance by free count, or nearest to destination.

Per-type pricing

Simple: Map<VehicleType, Long> of rates. Reach for PricingStrategy only for surge, discounts, daily caps.

Concurrent entrances

Good synchronized enter/exit, fine for 3–5 gates. Great atomic check-and-claim (Set.add returns false → retry) or per-type free queues as above. Across processes: DB SELECT … FOR UPDATE or a distributed lock.

Spot compatibility

"Motorcycle may use a car spot if motorcycle spots are full": replace the 1:1 switch with an ordered fallback list, e.g. MOTORCYCLE → [MOTORCYCLE, CAR, LARGE]. This is why the two enums are separate.

My suggestions

  1. Inject a Clock instead of calling System.currentTimeMillis(). It makes fee logic testable and is an easy senior signal in Java interviews.
  2. Watch the 0-minute edge case. The article's computeFee returns 0 if exit time equals entry time, though the text says "minimum 1 hour". Use Math.max(1, hours) and say it out loud.
  3. Use a record for Ticket and Instant/Duration instead of raw long millis. Mention long-cents for money before the interviewer does.
  4. Throw typed exceptions (NoSpotAvailableException, InvalidTicketException) rather than returning null or a generic Exception.
  5. Order of state changes matters. In enter, validate before mutating; in exit, remove the ticket first (atomically) so a concurrent second exit can't double-free the spot.
  6. Start with the baseline, then evolve. Present the linear scan + synchronized first, then offer the free-queue version when asked about scale or concurrency. Don't open with patterns nobody asked for.
  7. Don't add getAvailableSpots() or display-board methods unless asked. If asked, add a read-only count per type (an AtomicInteger or the queue size).
Time plan (~45 min): 5 requirements · 5 entities · 10 class design · 15 implementation · 5 trace / verify · 5 extensions.
